Every placeholder below is written in full, in the form PlaceholderAPI understands, and clicking one
copies it.

## Why the name says it twice

The plugin registers its placeholders under the group `staff`, and PlaceholderAPI puts the plugin's
own identifier in front of whatever it hands over. So through PlaceholderAPI, in a scoreboard plugin,
a tab plugin or anything else that asks, the name carries both:

```text
%exyliastaff_staff_reports_open%
```

Inside ExyliaStaff's own sidebars, menus and messages there is no PlaceholderAPI in the middle: the
library resolves the registered name directly, so the same placeholder is written without the plugin
name in front:

```text
%staff_reports_open%
```

Both spellings mean the same value. Which one to write depends only on who is reading the text: the
short one in this plugin's own files, the long one everywhere else. The per-module pages use the
short form, because the placeholders there sit next to that module's own YAML.

Every value is a memory read; nothing here touches the database. A placeholder of a module that is
off answers nothing.

## Core

| Placeholder | Value |
|---|---|
| `%exyliastaff_staff_mode%` | `true` while the viewer is in staff mode. |
| `%exyliastaff_staff_vanished%` | `true` while the viewer is vanished. |
| `%exyliastaff_staff_frozen%` | `true` while the viewer is frozen. |
| `%exyliastaff_staff_online%` | Players with `exyliastaff.staff` on this server. |
| `%exyliastaff_staff_in_mode%` | Players in staff mode on this server. |
| `%exyliastaff_staff_modules_enabled%` | Modules running. |

## In the sidebars

The default staff sidebar is one of this plugin's own files, so it writes the short form and mixes it
with the library's server placeholders: `%server_tps%`, `%server_mspt%`, `%server_cpu_process:percent%`,
`%server_ram_used%`, `%server_online%` and `%player_ping%`. Turning off the reports, helpop or vanish
module leaves its placeholder unresolved on the board; edit the line out.
