Nothing is declared in `plugin.yml`: commands are registered at runtime by the module that owns them,
so a module that is off has no commands at all.

`<x>` is required, `[x]` optional.

## Core

| Command | Aliases | Permission |
|---|---|---|
| `/survivalcore` | `/sc` | `survivalcore.admin` |
| `/survivalcore reload` | | `survivalcore.admin.reload` |

Runs from the console. It reloads the configs, the module settings and the menus — not the module
switches.

<Callout type="warning" title="`/bounty cancel` does not cancel">
It opens the same list `/bounty` opens. Cancel a contribution from the menu.
</Callout>

<Callout type="danger" title="`/stats` is never registered">
`/stats [player]` exists in the source but is missing the annotation that turns it into a command, so
the server never gets it — and `exyliasurvivalcore.stats` and `.stats.others` are unreachable with it.
The screens still open from the `survivalcore:stats_open` action.
</Callout>

## From the console

`/survivalcore`, every `*admin` command of farming, homes, kill rewards, playtime, rankup, reclaim and
RTP, and the five `/cratesadmin key` subcommands. Everything else is player-only.

## Tab completion

Thirteen suggestion providers fill in the arguments live: AFK zone ids, bounty ids, crate ids, farming
category ids, the player's own home names, another player's home names, kit ids, playtime reward ids,
rank ids, reclaim section ids, RTP world ids, online player names and warp ids.
