`config.yml` is two keys. That is the whole file.

```yaml
debug: false
modules:
  spawn: true
  tpa: true
  homes: true
  join-leave: true
  rtp: true
  kill-rewards: true
  scheduled-commands: true
  playtime-rewards: true
  rankup: true
  player-utils: true
  back: true
  farming: true
  reclaim: true
  stats: true
  portals: true
  jumpads: true
  kits: true
  bounties: true
  afk-zones: true
  item-spawners: true
  warps: true
  near: true
  loot-chests: true
  crates: true
  repair: true
  death: true
  powerups: true
  mines: true
  regen-zones: true
  enchantments: true
  blocked-items: true
  player-settings: true
```

`debug` adds console detail, including which actor each configured command line runs as. It is re-read
on `/sc reload`; the switches are not.

<Callout type="warning" title="A module switch needs a restart">
`/sc reload` re-reads the configuration files, the module settings and the menus, but it never enables
or disables a module. Change a switch and restart.
</Callout>

## What "off" means

A module that is off is never constructed past its own switch. It registers **no commands, no
listeners, no database tables, no placeholders and no timers**. Its own configuration file is left
alone on disk, so turning it back on picks up exactly where you left it.

A module id that nothing declares is simply off, which is not an error.

## What the switches do to each other

Modules are independent — none of them refuses to enable because another is off — but a few read each
other when they are both on.

<Callout type="note" title="`player-settings` is where seven broadcasts end up">
Rankups, bounties placed, bounties claimed, crate wins, deaths, reclaims, kill streaks and join/leave
messages all check the receiver's preferences before they are sent. With `player-settings` off, every
one of them goes to everybody, which is how the plugin behaved before that module existed.
</Callout>

<Callout type="note" title="`stats` feeds itself and PlaceholderAPI">
The `kdr` and `playtime` stats are computed from other stats and from a PlaceholderAPI name. With
`stats` off, nothing tracks kills or deaths and the leaderboards are empty; the kill-rewards streak is
counted separately and keeps working.
</Callout>

Turning off `crates`, `kits`, `mines` and the rest leaves everything they built in the database
untouched. Switching one back on brings its content back exactly as it was.
