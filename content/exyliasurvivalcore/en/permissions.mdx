---
title: "Permissions"
description: "Every node the plugin checks, module by module, the ones that carry a number, and the ones you write yourself in a config file."
---

Nothing is declared in `plugin.yml`. There is no `permissions:` block, so no node carries a
`default:` — an operator passes every check because operators pass every check, and everybody else
starts with nothing until a node is granted.

<Callout type="warning" title="Eight nodes still start with `survivalcore.`">
The prefix everywhere else is `exyliasurvivalcore.`, but the administration, rankup admin, farming
admin and portals admin nodes were written without it and are checked exactly as spelled below.
Grant them as they are; a `exyliasurvivalcore.admin` does nothing.
</Callout>

<Callout type="note" title="A disabled module checks nothing">
Modules register their own commands and listeners as they enable. A module turned off in
`config.yml` never registers, so its nodes are never read — granting them is harmless and changes
nothing until the module is back on.
</Callout>

`/playtime` and `/reclaim` have no node. What a player may reclaim is decided by the section
permissions instead — see [Sections, warps, kits and mines](#nodes-you-write-yourself).

<Callout type="warning" title="`/playtime` and `/reclaim` are open, and both of them write">
Neither command checks a node. `/reclaim` runs the commands of the highest-priority section whose
permission the player holds — so the section nodes are the only gate. `/playtime <rewardId>` **claims**
that reward; only having earned the playtime stops anybody.
</Callout>

<Callout type="danger" title="The two `stats` nodes cannot be used">
`/stats` is missing the annotation that would register it, so the server never has the command and
neither node is ever read. The screens still open through the `survivalcore:stats_open` action from any
menu.
</Callout>

<Callout type="danger" title="`bounties.anonymous` does nothing">
`/bounty place` works the flag out correctly from this node and `settings.allow-anonymous`, and hands
it to the confirmation screen — but the shipped `bounty_place_confirm.yml` passes `false` for it
regardless. Every bounty placed through the normal flow carries the placer's name.
</Callout>

## Nodes that carry a number

Three nodes end in a value rather than a word.

| Permission | Effect |
|---|---|
| `exyliasurvivalcore.homes.max_homes.<n>` | How many homes the player may set. The **highest** `<n>` they hold wins; with none, the `max-homes` in `modules/homes/config.yml` applies. |
| `exyliasurvivalcore.near.radius.<n>` | The radius `/near` searches. The **highest** `<n>` they hold wins, still capped by `max-radius` in `modules/near/config.yml`. |
| `exyliasurvivalcore.repair.group.<name>` | The repair prices and cooldowns of that group, out of `modules/repair/groups.yml`. |

```text
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.near.radius.500 true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
```

The repair groups are read in file order and the first group whose node the player holds is the one
that applies, so a player in two groups gets whichever is written higher in `groups.yml` — not the
cheaper one.

## Nodes you write yourself

Several things are gated by a node **you** choose, stored next to the thing it protects rather than
in the plugin's code.

| Where | Key | Default |
|---|---|---|
| A warp | Its `permission`, set through `/warpadmin` | Empty, which falls back to `exyliasurvivalcore.warps.use` |
| A kit | Its `permission`, set through `/kitadmin` | Empty, which means every holder of `exyliasurvivalcore.kits` |
| A mine | Its `permission`, set through `/minesadmin` | Empty, which means anybody may enter and mine it |
| A reclaim section | `sections.<id>.permission` in `modules/reclaim/config.yml` | `exyliasurvivalcore.reclaim.<id>` |
| A join / leave group | `groups.<id>.permission` in `modules/join-leave/groups.yml` | The shipped `vip` group names `survivalcore.joinleave.vip` — the short prefix |
| A rank requirement | A `PERMISSION` requirement's `node`, in the rankup config | None |

A mine's permission gates the whole region: without it nothing inside may be broken, minable or
not. `exyliasurvivalcore.mines.admin` passes both that check and the entry check.

The reclaim sections are picked by **priority**: a player is given the highest-priority section
whose permission they hold, so `vip` at `priority: 1` beats `usuario` at `priority: 0` for anybody
holding both.

### The warmup and RTP bypasses are config keys too

```yaml title="modules/spawn/config.yml"
settings:
  permission-bypass-warmup: exyliasurvivalcore.spawn.bypass
```

The same key exists in `modules/homes/config.yml` and `modules/back/config.yml`, defaulting to
`exyliasurvivalcore.homes.bypass` and `exyliasurvivalcore.back.bypass`. RTP has two of its own:

```yaml title="modules/rtp/config.yml"
settings:
  bypass-cooldown-permission: survivalcore.rtp.bypass
  bypass-price-permission: survivalcore.rtp.bypass
```

<Callout type="warning" title="Two declared nodes are never checked">
`exyliasurvivalcore.spawn` and `exyliasurvivalcore.rtp.bypass` exist in the code and nothing reads
them. `/spawn` is open to everybody, and the RTP bypass that is actually read is whatever
`modules/rtp/config.yml` names — `survivalcore.rtp.bypass` out of the box.
</Callout>

## A setup to start from

```text
# Everybody
/lp group default permission set exyliasurvivalcore.homes true
/lp group default permission set exyliasurvivalcore.homes.set true
/lp group default permission set exyliasurvivalcore.homes.del true
/lp group default permission set exyliasurvivalcore.homes.tp true
/lp group default permission set exyliasurvivalcore.homes.max_homes.2 true
/lp group default permission set exyliasurvivalcore.back true
/lp group default permission set exyliasurvivalcore.tpa true
/lp group default permission set exyliasurvivalcore.tpa.accept true
/lp group default permission set exyliasurvivalcore.tpa.deny true
/lp group default permission set exyliasurvivalcore.tpa.toggle true
/lp group default permission set exyliasurvivalcore.rtp true
/lp group default permission set exyliasurvivalcore.warps.use true
/lp group default permission set exyliasurvivalcore.kits true
/lp group default permission set exyliasurvivalcore.rankup true
/lp group default permission set exyliasurvivalcore.farming true
/lp group default permission set exyliasurvivalcore.stats true
/lp group default permission set exyliasurvivalcore.bounties.use true
/lp group default permission set exyliasurvivalcore.afkzones.use true
/lp group default permission set exyliasurvivalcore.near true
/lp group default permission set exyliasurvivalcore.repair.hand true
/lp group default permission set exyliasurvivalcore.playerutils.ping true

# VIP, on top of the above
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.tpa.here true
/lp group vip permission set exyliasurvivalcore.tpa.autoaccept true
/lp group vip permission set exyliasurvivalcore.playerutils.fly true
/lp group vip permission set exyliasurvivalcore.playerutils.ec true
/lp group vip permission set exyliasurvivalcore.repair.all true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
/lp group vip permission set exyliasurvivalcore.reclaim.vip true

# Staff
/lp group admin permission set survivalcore.admin true
/lp group admin permission set survivalcore.admin.reload true
/lp group admin permission set survivalcore.admin.homes true
/lp group admin permission set exyliasurvivalcore.mines.admin true
/lp group admin permission set exyliasurvivalcore.warps.admin true
/lp group admin permission set exyliasurvivalcore.kits.admin true
```

Grant `default` only what your players should have; every admin node above is one an operator
already passes without being granted anything.
