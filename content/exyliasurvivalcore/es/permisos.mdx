---
title: "Permisos"
description: "Todos los nodos que el plugin comprueba, módulo a módulo, los que llevan un número y los que escribes tú en un archivo de configuración."
---

No hay nada declarado en `plugin.yml`. No existe un bloque `permissions:`, así que ningún nodo tiene
`default:` — un operador pasa todas las comprobaciones porque los operadores pasan todas las
comprobaciones, y el resto no tiene nada hasta que le concedes cada nodo.

<Callout type="warning" title="Ocho nodos siguen empezando por `survivalcore.`">
El prefijo en todo lo demás es `exyliasurvivalcore.`, pero los nodos de administración, de rankup
admin, de farming admin y de portals admin se escribieron sin él y se comprueban exactamente como
están escritos abajo. Concédelos tal cual; un `exyliasurvivalcore.admin` no hace nada.
</Callout>

<Callout type="note" title="Un módulo desactivado no comprueba nada">
Cada módulo registra sus propios comandos y listeners al activarse. Un módulo apagado en
`config.yml` no registra nada, así que sus nodos no se leen nunca — concederlos no rompe nada y no
cambia nada hasta que el módulo vuelve a estar encendido.
</Callout>

## Nodos que llevan un número

Tres nodos terminan en un valor y no en una palabra.

| Permiso | Efecto |
|---|---|
| `exyliasurvivalcore.homes.max_homes.<n>` | Cuántos homes puede poner el jugador. Gana el `<n>` **más alto** que tenga; sin ninguno se aplica `max-homes` de `modules/homes/config.yml`. |
| `exyliasurvivalcore.near.radius.<n>` | El radio que busca `/near`. Gana el `<n>` **más alto** que tenga, siempre limitado por `max-radius` de `modules/near/config.yml`. |
| `exyliasurvivalcore.repair.group.<nombre>` | Los precios y cooldowns de reparación de ese grupo, de `modules/repair/groups.yml`. |

```text
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.near.radius.500 true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
```

Los grupos de reparación se leen en el orden del archivo y se aplica el primero cuyo nodo tenga el
jugador, así que quien esté en dos grupos se queda con el que esté escrito más arriba en
`groups.yml`, no con el más barato.

## Los nodos que escribes tú

Varias cosas las protege un nodo que eliges **tú**, guardado junto a lo que protege y no en el
código del plugin.

| Dónde | Clave | Por defecto |
|---|---|---|
| Un warp | Su `permission`, desde `/warpadmin` | Vacío, que cae en `exyliasurvivalcore.warps.use` |
| Un kit | Su `permission`, desde `/kitadmin` | Vacío, que significa cualquiera con `exyliasurvivalcore.kits` |
| Una mina | Su `permission`, desde `/minesadmin` | Vacío, que significa que cualquiera puede entrar y picar |
| Una sección de reclaim | `sections.<id>.permission` en `modules/reclaim/config.yml` | `exyliasurvivalcore.reclaim.<id>` |
| Un grupo de join / leave | `groups.<id>.permission` en `modules/join-leave/groups.yml` | Vacío, que no coincide con nadie |
| Un requisito de rango | El `node` de un requisito `PERMISSION`, en la configuración de rankup | Ninguno |

El permiso de una mina protege toda la región: sin él no se puede romper nada dentro, sea minable o
no. `exyliasurvivalcore.mines.admin` pasa esa comprobación y también la de entrada.

Las secciones de reclaim se eligen por **prioridad**: al jugador le toca la sección de mayor
prioridad cuyo permiso tenga, así que `vip` con `priority: 1` gana a `usuario` con `priority: 0`
para quien tenga las dos.

### Los bypass de warmup y de RTP también son claves de configuración

```yaml title="modules/spawn/config.yml"
settings:
  permission-bypass-warmup: exyliasurvivalcore.spawn.bypass
```

La misma clave existe en `modules/homes/config.yml` y `modules/back/config.yml`, con
`exyliasurvivalcore.homes.bypass` y `exyliasurvivalcore.back.bypass` por defecto. RTP tiene dos
propias:

```yaml title="modules/rtp/config.yml"
settings:
  bypass-cooldown-permission: survivalcore.rtp.bypass
  bypass-price-permission: survivalcore.rtp.bypass
```

<Callout type="warning" title="Hay dos nodos declarados que no se comprueban nunca">
`exyliasurvivalcore.spawn` y `exyliasurvivalcore.rtp.bypass` existen en el código y no los lee
nadie. `/spawn` está abierto a todo el mundo, y el bypass de RTP que sí se lee es el que nombre
`modules/rtp/config.yml` — `survivalcore.rtp.bypass` de salida.
</Callout>

## Una configuración de la que partir

```text
# Todo el mundo
/lp group default permission set exyliasurvivalcore.homes true
/lp group default permission set exyliasurvivalcore.homes.set true
/lp group default permission set exyliasurvivalcore.homes.del true
/lp group default permission set exyliasurvivalcore.homes.tp true
/lp group default permission set exyliasurvivalcore.homes.max_homes.2 true
/lp group default permission set exyliasurvivalcore.back true
/lp group default permission set exyliasurvivalcore.tpa true
/lp group default permission set exyliasurvivalcore.tpa.accept true
/lp group default permission set exyliasurvivalcore.tpa.deny true
/lp group default permission set exyliasurvivalcore.tpa.toggle true
/lp group default permission set exyliasurvivalcore.rtp true
/lp group default permission set exyliasurvivalcore.warps.use true
/lp group default permission set exyliasurvivalcore.kits true
/lp group default permission set exyliasurvivalcore.rankup true
/lp group default permission set exyliasurvivalcore.farming true
/lp group default permission set exyliasurvivalcore.stats true
/lp group default permission set exyliasurvivalcore.bounties.use true
/lp group default permission set exyliasurvivalcore.afkzones.use true
/lp group default permission set exyliasurvivalcore.near true
/lp group default permission set exyliasurvivalcore.repair.hand true
/lp group default permission set exyliasurvivalcore.playerutils.ping true

# VIP, encima de lo anterior
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.tpa.here true
/lp group vip permission set exyliasurvivalcore.tpa.autoaccept true
/lp group vip permission set exyliasurvivalcore.playerutils.fly true
/lp group vip permission set exyliasurvivalcore.playerutils.ec true
/lp group vip permission set exyliasurvivalcore.repair.all true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
/lp group vip permission set exyliasurvivalcore.reclaim.vip true

# Staff
/lp group admin permission set survivalcore.admin true
/lp group admin permission set survivalcore.admin.reload true
/lp group admin permission set survivalcore.admin.homes true
/lp group admin permission set exyliasurvivalcore.mines.admin true
/lp group admin permission set exyliasurvivalcore.warps.admin true
/lp group admin permission set exyliasurvivalcore.kits.admin true
```

Dale a `default` solo lo que quieras que tengan tus jugadores; todos los nodos de administración de
arriba ya los pasa un operador sin que le concedas nada.
