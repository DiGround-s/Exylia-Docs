`config.yml` son dos claves. Eso es el archivo entero.

```yaml
debug: false
modules:
  spawn: true
  tpa: true
  homes: true
  join-leave: true
  rtp: true
  kill-rewards: true
  scheduled-commands: true
  playtime-rewards: true
  rankup: true
  player-utils: true
  back: true
  farming: true
  reclaim: true
  stats: true
  portals: true
  jumpads: true
  kits: true
  bounties: true
  afk-zones: true
  item-spawners: true
  warps: true
  near: true
  loot-chests: true
  crates: true
  repair: true
  death: true
  powerups: true
  mines: true
  regen-zones: true
  enchantments: true
  blocked-items: true
  player-settings: true
```

`debug` añade detalle en consola, incluido con qué actor se ejecuta cada línea de comando configurada.
Se relee con `/sc reload`; los interruptores no.

<Callout type="warning" title="Un interruptor de módulo necesita reinicio">
`/sc reload` relee los archivos de configuración, los ajustes de cada módulo y los menús, pero nunca
enciende ni apaga un módulo. Cambia un interruptor y reinicia.
</Callout>

## Qué significa "apagado"

Un módulo apagado no se construye más allá de su propio interruptor. No registra **ni comandos, ni
listeners, ni tablas, ni placeholders, ni temporizadores**. Su archivo de configuración se queda intacto
en disco, así que volver a encenderlo retoma exactamente donde lo dejaste.

Un id de módulo que nadie declara está simplemente apagado, y eso no es un error.

## Qué se hacen entre ellos

Los módulos son independientes — ninguno se niega a arrancar porque otro esté apagado — pero unos
cuantos se leen entre sí cuando los dos están encendidos.

<Callout type="note" title="`player-settings` es donde acaban siete anuncios">
Rankups, recompensas puestas, recompensas cobradas, premios de caja, muertes, reclaims, rachas de bajas
y mensajes de entrada y salida comprueban las preferencias de quien los recibe antes de mandarse. Con
`player-settings` apagado, todos van a todo el mundo, que es como se comportaba el plugin antes de que
existiera ese módulo.
</Callout>

<Callout type="note" title="`stats` se alimenta a sí mismo y de PlaceholderAPI">
Las stats `kdr` y `playtime` se calculan a partir de otras stats y de un nombre de PlaceholderAPI. Con
`stats` apagado no se registran bajas ni muertes y los rankings están vacíos; la racha de kill-rewards
se cuenta aparte y sigue funcionando.
</Callout>

Apagar `crates`, `kits`, `mines` y los demás deja intacto en la base de datos todo lo que construyeron.
Volver a encender uno lo devuelve exactamente como estaba.
