---
title: "API"
description: "ArmorSkinAPI: registrar skins y tipos de animación desde código, construir objetos de skin, aplicar y quitar skins y redibujar a un jugador."
---

Todo lo que necesita otro plugin está en una clase, `net.exylia.exyliaArmorSkin.api.ArmorSkinAPI`.

```java
import net.exylia.exyliaArmorSkin.api.ArmorSkinAPI;

ArmorSkinAPI api = ArmorSkinAPI.get();
```

`get()` lanza `IllegalStateException` mientras el plugin no está activo, así que añade
`softdepend: [ExyliaArmorSkin]` a tu `plugin.yml` y llámalo desde `onEnable` o después.

## Skins

```java
import net.exylia.exyliaArmorSkin.skin.SkinDefinition;
import org.bukkit.Color;

SkinDefinition ruby = new SkinDefinition(
        "ruby",                                   // id, comparado en minúsculas
        "{error}&lRUBY",                          // nombre
        java.util.Set.of(),                       // piezas: vacío significa las cuatro
        new SkinDefinition.Look(Color.fromRGB(0xC0102A), "ward", "redstone"),
        SkinDefinition.Effects.NONE);

api.register(ruby);
```

| Método | Devuelve | Qué hace |
|---|---|---|
| `register(SkinDefinition)` | — | Añade o reemplaza una skin. Sobrevive a `/armorskinsadmin reload`. |
| `unregister(String id)` | `boolean` | Quita una, venga del código o del archivo. |
| `skin(String id)` | `Optional<SkinDefinition>` | Busca una. |
| `exists(String id)` | `boolean` | Si un id resuelve. |
| `registry()` | `SkinRegistry` | El registro en sí: `all()`, `ids()`, `onChange(listener)`. |

<Callout type="note" title="Código y archivo conviven">
Una recarga reemplaza solo las entradas que venían de `skins.yml`. Una skin registrada aquí se queda
hasta que se desregistre o el servidor pare, y `/armorskinsadmin list` la muestra como a cualquier otra.
</Callout>

### Qué contiene una definición

| Componente | Tipo | Notas |
|---|---|---|
| `id` | `String` | Se guarda en la armadura. Se compara sin espacios y en minúsculas. |
| `name` | `String` | Admite tokens de paleta y códigos `&`. |
| `pieces` | `Set<ArmorPiece>` | `HELMET`, `CHESTPLATE`, `LEGGINGS`, `BOOTS`. **Un conjunto vacío pasa a ser las cuatro.** |
| `look` | `Look` | `color`, `trimPattern`, `trimMaterial` — las claves de trim se resuelven al dibujar. `Look.PLAIN` para ninguno. |
| `effects` | `Effects` | `onEquip`, `onUnequip`, `ambient`, `set`. `Effects.NONE` para ninguno, y un constructor de tres argumentos deja el bonus de set vacío. |
| `animation` | `SkinAnimation` | Opcional, `null` para color fijo. |
| `icon` | `String` | Material opcional del objeto de skin, `null` para usar `skin-item.material`. |

Hay tres constructores: sin animación ni icono, con animación, y con los dos.

`Effects.set` es un `SetBonus(EffectConfig onComplete, EffectConfig onBreak, Ambient ambient)`: lo que
suena cuando todas las piezas que la skin encaja se llevan con ella, lo que suena mientras dura y lo
que suena al terminar. `SetBonus.NONE` es el vacío.

`permission()` devuelve el nodo que permite usar la skin, `exyliaarmorskin.skin.<id>` con el id en
minúsculas. Es derivado, nunca almacenado, así que una skin registrada aquí tiene nodo como cualquier
otra.

## Tipos de animación

```java
import net.exylia.exyliaArmorSkin.skin.SkinAnimation;
import net.exylia.exyliaArmorSkin.skin.animation.AnimationSpec;

api.animations().register("strobe2", spec -> new SkinAnimation() {
    @Override public long intervalTicks() { return spec.intervalTicks(); }
    @Override public org.bukkit.Color colorAt(long frame, org.bukkit.Color base) {
        return frame % 2 == 0 ? org.bukkit.Color.WHITE : org.bukkit.Color.BLACK;
    }
});
```

Un tipo registrado se puede usar al momento desde `animations.yml` como `type: strobe2`, y desde
código:

```java
SkinAnimation animation = api.animations()
        .create("rainbow", new AnimationSpec(2, java.util.List.of(), java.util.Map.of()))
        .orElseThrow();
```

| Método de `animations()` | Qué hace |
|---|---|
| `register(String, Function<AnimationSpec, SkinAnimation>)` | Añade un tipo. |
| `unregister(String)` | Quita uno. |
| `has(String)` / `types()` | Qué tipos existen. |
| `resolve(String)` | Primero un preset de `animations.yml`, si no un tipo directo con sus valores por defecto. |
| `create(String type, AnimationSpec)` | Construye una desde un spec. |

`AnimationSpec` es `(long intervalTicks, List<Color> colors, Map<String, String> options)`, con el
intervalo con suelo de un tick y `option(name, fallback)` para leer números y booleanos.

## Objetos

| Método | Devuelve | Qué hace |
|---|---|---|
| `skinItem(String id, Player viewer)` | `Optional<ItemStack>` | El objeto de skin, renderizado para ese jugador. |
| `remover(Player viewer)` | `ItemStack` | Un removedor. |
| `isSkinItem(ItemStack)` | `boolean` | Si una pila es un objeto de skin. |
| `isRemover(ItemStack)` | `boolean` | Si una pila es un removedor. |
| `skinId(ItemStack)` | `Optional<String>` | El id de un objeto de skin **o** de una armadura con skin. |
| `hasSkin(ItemStack armor)` | `boolean` | Si una pieza de armadura lleva skin. |

## Aplicar y quitar

```java
ApplyResult result = api.apply(chestplate, "ruby");
if (result.success()) {
    // el peto sigue igual salvo por un valor de datos
}
```

| Método | Qué hace |
|---|---|
| `apply(ItemStack armor, String skinId)` | Aplica una skin por id. |
| `apply(ItemStack armor, ItemStack skinItem)` | Aplica la skin que lleva un objeto de skin. El objeto no se consume. |
| `remove(ItemStack armor, Player receiver)` | Quita la skin y la devuelve como objeto. |
| `strip(ItemStack armor)` | Quita la skin sin devolver nada. |

Todas las comprobaciones se hacen antes de escribir nada, así que una llamada que falla deja las dos
pilas exactamente como estaban. La armadura se modifica in situ.

<Callout type="warning" title="La API ignora los permisos por skin, la visualización no">
`apply()` nunca comprueba `exyliaarmorskin.skin.<id>`: es la herramienta con la que concedes una
skin. Pero con `hide-without-permission: true`, a un portador sin ese nodo se le sigue mostrando la
armadura real, así que concede el nodo junto con la skin salvo que la quieras invisible.
</Callout>

### `ApplyResult`

| Valor | Significado |
|---|---|
| `APPLIED` | La skin se escribió. |
| `REMOVED` | La skin se borró. |
| `NOT_ARMOR` | La pila no es una pieza de armadura equipable — o es un objeto de skin. |
| `UNSUPPORTED_PIECE` | La skin no incluye esa ranura. |
| `UNKNOWN_SKIN` | No hay ninguna skin registrada con ese id. |
| `INVALID_ITEM` | La pila pasada como objeto de skin no lo es, o no lleva id. |
| `ALREADY_SKINNED` | La armadura ya lleva una skin. |
| `NO_SKIN` | La armadura no lleva skin. |
| `INVENTORY_FULL` | El receptor no tiene ranura libre; no se cambió nada. |
| `NO_PERMISSION` | Al jugador le falta el nodo de la skin. Solo lo devuelve el arrastre en el inventario, nunca la API. |

`success()` es cierto para `APPLIED` y `REMOVED`.

## El vestidor

| Método | Devuelve | Qué hace |
|---|---|---|
| `wardrobe()` | `Wardrobe` o `null` | El vestidor, o `null` mientras `behaviour.mode` sea `item`. |
| `wear(Player, ArmorPiece, String skinId)` | `ApplyResult` | Pone una skin en una ranura, o en todas las que el jugador pueda usar cuando la pieza es `null`. |
| `undress(Player, ArmorPiece)` | `ApplyResult` | Limpia una ranura, o el vestidor entero cuando la pieza es `null`. |
| `chosen(Player, ArmorPiece)` | `Optional<String>` | La skin elegida para esa ranura, lleve lo que lleve puesto. |

Escriben en la fila del jugador, nunca en la armadura. Con el vestidor apagado, `wear` responde
`UNKNOWN_SKIN`, `undress` responde `NO_SKIN` y `chosen` viene vacío.

## Redibujar

| Método | Qué hace |
|---|---|
| `refresh(Player)` | Reconstruye los visuales de ese jugador desde su armadura real y se los reenvía. |
| `refreshAll()` | Lo mismo para todos los conectados. |

Llama a `refresh` después de cambiar una pieza equipada por detrás del plugin: el evento de cambio de
armadura cubre equipar y desequipar, pero no un objeto que reescribiste in situ mientras estaba
puesto.

## Qué se guarda en el objeto

Un valor de datos persistentes bajo el namespace del plugin:

| Clave | En | Valor |
|---|---|---|
| `exyliaarmorskin:skin` | Armadura y objetos de skin | El id de la skin. |
| `exyliaarmorskin:item` | Solo objetos de skin y removedores | `skin` o `remover`. |

La armadura se distingue de un objeto de skin por la segunda clave: una pila que lleva las dos es un
objeto de skin, nunca armadura con skin.
