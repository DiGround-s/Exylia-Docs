title: "Commands"
description: "Every command the plugin registers, its arguments, its aliases and the node it checks."
---

Nothing is declared in `plugin.yml`: every command is registered at runtime, so the arguments below are
what tab completion offers and the nodes are checked by the command itself.

## Player commands

| Command | Aliases | Permission | What it does |
|---|---|---|---|
| `/rtp` | — | `exyliasandbox.command.rtp` | Opens the world list |
| `/rtp <world>` | — | `exyliasandbox.command.rtp` | Straight into that world. Refused if it is not `READY` |
| `/rtpqueue` | — | `exyliasandbox.command.rtpqueue` | Opens the world list, joins that world's queue |
| `/rtpqueuefast` | — | `exyliasandbox.command.rtpqueuefast` | Joins a queue, picking the world for you |
| `/leavertpqueue` | — | `exyliasandbox.command.leavertpqueue` | Leaves the queue |
| `/leavesandbox` | — | `exyliasandbox.command.leavesandbox` | Back to the lobby |
| `/tpa <player>` | — | `exyliasandbox.command.tpa` | Asks to be teleported to a player inside a sandbox |
| `/tpaccept [player]` | — | `exyliasandbox.command.tpa` | Accepts. With no name, the newest request still alive |
| `/tpdeny [player]` | — | `exyliasandbox.command.tpa` | Denies. Same selection |
| `/back` | — | `exyliasandbox.command.back` | Back to your last spot inside a sandbox |
| `/rekit` | — | `exyliasandbox.command.rekit` | Re-applies the kit you are wearing, and heals you |
| `/kitroom [category]` | — | `exyliasandbox.command.kitroom` | Opens the kit room, optionally on one category |
| `/kitcreator` | — | `exyliasandbox.command.kitcreator` | Opens your kit slots |
| `/kitsave` | — | `exyliasandbox.command.kitcreator` | Saves what you are carrying into the slot you entered |
| `/predefinedkits [kit] [slot]` | `/predefinedkit`, `/pkits` | `exyliasandbox.command.predefinedkits` | The admin templates. With both arguments, copies one straight into a slot |

Tab completion is live: `<world>` offers every configured world id, `/tpa <player>` offers players
inside loaded sandbox worlds, `/tpaccept` offers the names of people waiting on you, `/kitroom` offers
the category ids and `/predefinedkits` offers the templates that have contents.

`/tpdeny` has no completion.

## Admin commands

| Command | Permission | What it does |
|---|---|---|
| `/sandbox` | `exyliasandbox.admin` | Opens the admin panel |
| `/sandbox predefinedkits` | `exyliasandbox.admin` | Opens the template list directly |
| `/sandbox reload` | `exyliasandbox.admin` | Re-reads the configs and recompiles the menus. Runs from the console |

Exporting and importing the plugin's data is not a command of this plugin: use ExyliaLib's
`/exylialib export` and `/exylialib import`.

## The command whitelist

While a player is inside a sandbox world **or waiting in a queue**, only the commands listed in
`config.yml` → `command-whitelist.commands` are allowed. Everything else is refused with
`general.command-blocked`.

Matching is on the first word, lowercased, and a `plugin:` prefix is stripped first — so `minecraft:tp`
is blocked exactly as `tp` is.

The shipped list:

```yaml
command-whitelist:
  enabled: true
  commands:
    - msg
    - message
    - tell
    - w
    - whisper
    - reply
    - r
    - respond
    - sandbox
    - rtp
    - rtpqueue
    - rtpqueuefast
    - back
    - tpa
    - tpaccept
    - tpdeny
    - rekit
    - leavesandbox
    - leavertpqueue
    - kitcreator
    - kitsave
    - kitroom
    - bot
    - leave
```

`exyliasandbox.bypass.blocked-commands` skips the whitelist entirely.

<Callout type="note" title="`/predefinedkits` is not on the shipped list">
Neither `predefinedkits` nor its two aliases are whitelisted, so they are blocked inside a sandbox
world. That is harmless — copying a template is something you do in the lobby — but add them to the
list if you want the command reachable from inside.
</Callout>
