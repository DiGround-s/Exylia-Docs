title: "Introduction"
description: "What ExyliaSandBox is: generated PvP worlds, a random-teleport entry, a 1v1 queue, saved kits and a kit room."
---

ExyliaSandBox turns a Paper or Folia server into a set of disposable PvP worlds. The plugin generates
the terrain itself, drops players into it with `/rtp`, dresses them in a kit they saved beforehand, and
throws them back to the lobby the moment they die. Nothing in a sandbox world is meant to last: chunks
are not saved, death cancels the vanilla death entirely, and the world can be deleted and rebuilt from
the admin panel.

It ships **five worlds, five terrain presets, seven database tables, nineteen menus and eighteen
commands**. Everything an admin configures lives behind one `/sandbox` menu tree — there is no world
list to edit by hand.

## What it does

<Cards>
  <Card title="Generated worlds" href="/docs/exyliasandbox/worlds">
    A custom generator with every vanilla stage turned off: flat-ish terrain, one biome, a layer stack
    and a decoration pass you pick from five presets.
  </Card>
  <Card title="Random teleport" href="/docs/exyliasandbox/rtp-and-queue">
    `/rtp` finds a safe spot inside the border, claims the player, dresses them in a kit and sends them.
  </Card>
  <Card title="A 1v1 queue" href="/docs/exyliasandbox/rtp-and-queue">
    `/rtpqueue` pairs two players at a fixed distance, facing each other. `/rtpqueuefast` picks the world
    for them.
  </Card>
  <Card title="Kits players write" href="/docs/exyliasandbox/kits">
    A kit creator, a permission-tiered number of slots, a favourite, and admin templates a player copies
    into a slot of their own.
  </Card>
  <Card title="A kit room" href="/docs/exyliasandbox/kit-room">
    A shelf of pre-enchanted gear in categories, used while building a kit. Taking from it never empties it.
  </Card>
  <Card title="Teleport pads" href="/docs/exyliasandbox/tp-regions">
    A cuboid in the lobby with a hologram, a boss bar and a countdown that sends everybody standing on it
    at once.
  </Card>
  <Card title="Movement inside" href="/docs/exyliasandbox/teleports">
    `/tpa` to a player already inside, `/back` to where you last were, `/rekit` to put the kit back on.
  </Card>
  <Card title="The admin panel" href="/docs/exyliasandbox/admin-panel">
    `/sandbox`: worlds, gamerules, players, teleport pads, predefined kits, kit-room categories, lobby.
  </Card>
</Cards>

## The shape of a session

<Steps>
  <Step title="A kit first">
    `/kitcreator` opens the player's slots. They enter one, take gear from the kit room, and `/kitsave`
    stores the whole inventory — storage, armour and offhand. How many slots they get is a permission.
  </Step>
  <Step title="In">
    `/rtp` picks a world, `/rtpqueue` waits for an opponent, or they stand on a teleport pad and let the
    countdown do it. Their inventory is snapshotted and cleared, the kit goes on, and a safe location is
    searched inside the border.
  </Step>
  <Step title="Fighting">
    PvP is forced on in every sandbox world, the sidebar shows kills, deaths, KDR, playtime and the
    border, and the command whitelist keeps them from running anything that is not on the list.
  </Step>
  <Step title="Out">
    Death, `/leavesandbox` or a disconnect all end the same way: back to the lobby, inventory restored,
    the claim released. The death itself is cancelled, so there is no respawn screen and nothing drops.
  </Step>
</Steps>

## At a glance

| | |
|---|---|
| Version documented | 1.0.3 |
| Minecraft | 1.21+ |
| Platforms | Spigot, Paper and Folia |
| Required | `ExyliaLib`, `Chunky`, `packetevents` |
| Optional | `PlaceholderAPI`, `ExyliaPracticeCore`, the `Worlds` plugin on Folia |
| Database | H2 by default; MySQL, MariaDB, PostgreSQL and MongoDB through ExyliaLib |

## How this documentation is organised

**Getting started** installs the plugin and builds the first world and the first kit. **Configuring**
has one page per thing an admin owns: worlds, kits, the kit room and the teleport pads. **Systems**
covers what a player actually does: the RTP and its queue, the teleport commands, and the admin panel
screen by screen. **Reference** is the flat lists — commands, permissions, placeholders, the generated
config files, the menus, the tables, the API and the questions that come up.

<Callout type="note" title="Where the numbers come from">
Every default, message, node and rule on these pages was read from the plugin's source at version
1.0.3. Where a page says a value is not configurable, that is because no key exists for it.
</Callout>
