Nothing is declared in `plugin.yml`. There is no `permissions:` block, so no node carries a `default:`
— an operator passes every check because operators pass every check, everybody else starts with
nothing, and none of these nodes appears in a permission plugin's tab completion.

## Administration

| Permission | Description |
|---|---|
| `exyliasandbox.admin` | `/sandbox` and every button in every admin screen |

There is no finer-grained admin node. The same one covers creating worlds, deleting them, editing kit
templates, moving the lobby and reloading.

## Kits

| Permission | Description |
|---|---|
| `exyliasandbox.command.kitroom` | `/kitroom` |
| `exyliasandbox.command.kitcreator` | `/kitcreator` and `/kitsave` |
| `exyliasandbox.command.predefinedkits` | `/predefinedkits`, `/predefinedkit`, `/pkits` |
| `exyliasandbox.max_kits.<n>` | How many kit slots the player gets |

### How `max_kits` resolves

The plugin walks down from `exyliasandbox.max_kits.100` to `exyliasandbox.max_kits.1` and takes the
**first** node the player holds. So:

- the highest node a player holds is the one that counts — `.3` and `.5` together give five;
- a node above 100 is never read;
- a player with no node at all gets **one** slot.

Grant exactly one node per group.

<Callout type="note" title="It is a hundred lookups">
The walk is a hundred permission checks, run every time the kit creator or a copy screen opens. It is
not free on a permission plugin that answers slowly, but it is bounded and it never runs in a loop.
</Callout>

## Bypass

| Permission | Description |
|---|---|
| `exyliasandbox.bypass.blocked-commands` | Run any command inside a sandbox world or a queue, ignoring the whitelist |
