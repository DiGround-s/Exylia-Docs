ExyliaFFA is a free-for-all system built for servers that take it seriously: unlimited arenas,
multiple kits, permission-gated spawns, per-arena rules, schematic-based regeneration, persistent
stats and a full admin panel driven from in-game menus.

It is not a single-arena plugin with a join command. Each arena is an independent configuration: its
own rules, its own kits, its own spawns, its own spawn protection and its own regeneration timer.

## What is included

  <Card title="Unlimited arenas" href="/docs/exyliaffa/arenas">

    Several spawn points per arena, each with its own icon, display name and permission.
  </Card>

  </Card>

## Requirements

| Requirement | Detail |
|---|---|
| Server | Paper 1.21 or newer. Folia supported. |
| Java | 21 |
| Required dependencies | `ExyliaLib`, `FastAsyncWorldEdit`, `packetevents` |
| Optional dependencies | `PlaceholderAPI`, `ViaVersion`, `ExyliaPracticeCore`, `ExyliaEvents`, `ExyliaSandBox` |

<Callout type="note" title="About ExyliaLib">
ExyliaLib is not a decorative dependency. Typed configuration with migrations, declarative YAML
menus, the database, placeholders, effects and actions all come from it. Without it, the plugin does
not start.
</Callout>

## Conventions

- Values marked as **default** are what the plugin writes the first time it starts. If the file
  already exists, your value is kept.
- Identifiers between `<` and `>` are variables. `/ffa join <arenaId>` means `/ffa join nodebuff`,
  not `/ffa join <nodebuff>`.
- Colours use ExyliaLib palette tokens (`{primary}`, `{highlight}`, `{muted}`) and also accept
  MiniMessage and hexadecimal codes.
