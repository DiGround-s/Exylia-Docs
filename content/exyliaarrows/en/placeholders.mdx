---
title: "Placeholders"
description: "Six PlaceholderAPI placeholders, and what they answer when nothing is chosen."
---

Every placeholder below is written in full, and clicking one copies it.

| Placeholder | Description |
|---|---|
| `%exyliarrows_effect%` | The chosen effect's id. |
| `%exyliarrows_effect_name%` | Its display name, with its colours. |
| `%exyliarrows_effect_category%` | The category id. |
| `%exyliarrows_effect_category_name%` | The category's display name. |
| `%exyliarrows_effect_icon%` | The item it is drawn with. |
| `%exyliarrows_has_effect%` | `true` or `false`. |

## With nothing chosen

`has_effect` returns `false`; everything else returns whatever `placeholders.none` says in
`config.yml` — `None` by default.

```yaml
lines:
  - " {muted}❙ {letters}Arrow: {highlight}%exyliarrows_effect_name%"
```

<Callout type="note" title="No description placeholder here">
The kill and hit plugins expose `effect_description`; this one does not. What it has instead is
`effect_icon`, which is the menu item — useful for a menu in another plugin that wants to draw the
player's current choice.
</Callout>

## Reading it from code

`ArrowsAPI` is the small public surface, for a plugin that wants to set or read a selection:

```java
ArrowsAPI.getEffect("fire_trail");
ArrowsAPI.getAllEffects();
ArrowsAPI.getPlayerData(uuid);
ArrowsAPI.setPlayerEffect(player, "fire_trail");
ArrowsAPI.resetPlayerEffect(player);
```

`setPlayerEffect` is the one worth noting: it is how a crate, a quest reward or a rank plugin hands
somebody an effect without going through the menu.
