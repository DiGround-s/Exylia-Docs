ExyliaTotemTrainer is a totem-pop trainer for servers that take PvP practice seriously. A player
trains alone at a tick speed they pick, in a mode the server owner defines, or challenges another
player to a best-of duel decided by the totem alone. Every session is graded, every best is kept,
and every mode has its own leaderboard.

It is not a kit with totems in it. Every configured number of ticks the plugin deals a lethal hit that
a totem in either hand absorbs; the player has to get the next one into a hand before the next hit,
and the time that takes is the reaction that is graded. No totem in hand when a hit lands is a fail:
in training the session ends, in a duel the round is lost. No death screen is ever shown.

## Requirements

| Requirement | Detail |
|---|---|
| Server | Paper 1.21 or newer. Folia supported. |
| Java | 21 |
| Required dependencies | `ExyliaLib`, `packetevents` |
| Optional dependencies | `PlaceholderAPI` |

<Callout type="note" title="About ExyliaLib">
Typed configuration, declarative YAML menus, the database, placeholders, effects, sidebars, inventory
snapshots and the player claims that keep Exylia plugins from stepping on each other all come from
ExyliaLib. The plugin is written on top of it and does not run without it.
</Callout>

## Conventions

- Values marked as **default** are what the plugin writes the first time it starts. If the file
  already exists, your value is kept.
- Identifiers between `<` and `>` are variables. `/totem train <mode>` means `/totem train chaos`,
  not `/totem train <chaos>`.
- Times are seconds with decimals unless a key says ticks; 20 ticks are one second.
- Colours use ExyliaLib palette tokens (`{primary}`, `{highlight}`, `{muted}`); MiniMessage tags such
  as `<click>` and `<hover>` work too, as the default duel request shows.
