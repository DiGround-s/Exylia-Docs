## Player commands

`/killeffect`, with the aliases `killeffects`, `deatheffect` and `deatheffects`. Everything under it
needs `exyliakilleffect.command.killeffect`.

| Command | What it does |
|---|---|
| `/killeffect` | Opens the menu, on the tab it was last left on. |
| `/killeffect crate` | Opens the crate, the same screen the button in the menu opens. Aliases: `crates`, `case`. |
| `/killeffect preview <effect>` | Plays an effect on the server's preview stage. Owning it is not required. |
| `/killeffect visibility [mode]` | Sets who sees kill effects for them. With no mode it steps to the next one. |
| `/killeffect random` | Plays a different effect on every kill, or stops when it is already on. Alias: `shuffle`. |
| `/killeffect favourites` | Opens the menu straight onto the shortlist. Aliases: `favorites`, `favs`. |
| `/killeffect favourite <effect>` | Stars an effect, or unstars it. Aliases: `favorite`, `fav`. |
| `/killeffect favourites clear` | Empties the shortlist. |
| `/killeffect clear` | Takes the effect off. |

## Admin commands

`/killeffectsadmin`, alias `/killeffectadmin`. Everything under it needs `exyliakilleffect.admin`.
Subcommands are grouped by what they act on: the items, the weapon in hand, a player, their keys,
what they own, the crate, the screens and the previews.

### `item` — the items this plugin hands out

| Command | What it does |
|---|---|
| `item give <player> <effect> [1-64]` | Gives effect tokens. |
| `item remover <player> [1-64]` | Gives effect removers. |

### `weapon` — the weapon in the target's hand

| Command | What it does |
|---|---|
| `weapon bind <effect> [player]` | Binds an effect to the weapon in hand, replacing whatever it carried. |
| `weapon unbind [player]` | Strips the effect from the weapon in hand, giving nothing back. |

### `player` — what somebody wears

| Command | What it does |
|---|---|
| `player set <player> <effect>` | Sets what a player wears. |
| `player clear <player>` | Takes a player's effect off. |
| `player favourites clear <player>` | Empties a player's shortlist. |
| `player validate [player]` | Takes off an effect the target may no longer use. With no player, everyone online. |

### `keys` — what opens crates

| Command | What it does |
|---|---|
| `keys give <player> <amount>` | Adds crate keys. Alias: `keys add`. |
| `keys take <player> <amount>` | Removes crate keys. Alias: `keys remove`. |
| `keys set <player> <amount>` | Sets how many they hold. |
| `keys check <player>` | Prints how many they hold. Alias: `keys`. |

### `unlocks` — what somebody owns

| Command | What it does |
|---|---|
| `unlocks grant <player> <effect>` | Hands an effect over outright, the way a crate does. Alias: `unlocks give`. |
| `unlocks revoke <player> <effect>` | Takes one back. Alias: `unlocks take`. |
| `unlocks clear <player>` | Takes everything they won back. |

### `crate` — the blocks that open it

| Command | What it does |
|---|---|
| `crate block add` | Binds the block you are looking at, so clicking it opens the crate. |
| `crate block remove` | Unbinds the block you are looking at. |
| `crate block list` | Prints every bound block. |
| `crate block clear` | Unbinds all of them. |

### `menu` and `preview`

| Command | What it does |
|---|---|
| `menu open <player>` | Opens the effects menu for someone. |
| `menu crate <player>` | Opens the crate screen for someone, without spending anything. |
| `preview play <effect> [player]` | Previews an effect, for yourself or for someone else. |
| `preview location` | Sets the preview stage to where you stand. Only the position is taken. |

### The rest

| Command | What it does |
|---|---|
| `list [category]` | Prints every effect, or just one category's. |
| `refresh [player]` | Redraws what a player is holding. With no player, everyone online. |
| `reload` | Re-reads this plugin's files. |

<Callout type="note" title="bind, set and give ignore permissions">
They are admin verbs: a crate, a rank reward or a support ticket has already decided the player may
have the effect. `require-permission` governs what a **player** can do, never what an admin or the
API does.
</Callout>

## What each one actually does

### `weapon bind`

Acts on the target's main hand. An empty hand answers `empty-hand`. A weapon that already carries an
effect has it replaced — the old one is dropped, not returned as a token. The weapon that does not fit
the effect's `weapons` list is refused.

### `weapon unbind`

Strips the value and hands nothing back, which is the difference from a remover item. For giving the
token back, have the player use a remover.

### `player validate`

Re-checks the target's choice against their permissions and takes it off if it no longer holds. The
same check runs on join, on the next kill and on every menu open — `player validate` is how you make it
immediate after changing a rank.


### `crate block add`

Binds the block you are looking at, up to six blocks away, and writes it to `config.yml` rather than
into the world — so it survives a schematic paste, a world edit and a rollback. While a block is
bound it cannot be broken, blown up or pushed away, and clicking it no longer does what its material
does: a crate drawn on a barrel must not open a barrel.

### `preview location`

Stores where previews play: where you stand. Only the position is taken — a preview always faces
north, so every effect is seen from the side it was drawn for, and the north side of the stage is the
one to leave open. Until one is set,
`/killeffect preview` answers `preview-unavailable` rather than staging an effect on top of whoever asked to see
it. Admins are told which command sets it.

### `refresh`

Re-sends the player's inventory so the lines under a bound weapon are redrawn. It touches no file and
plays no effect: it is the answer to a weapon whose line went stale.

### `reload`

Runs one step, `configs`, which re-reads `config.yml`, `effects.yml` and the files in `menus/`,
recompiles every sequence and reapplies the message prefix. Edits made to the menu file survive.

It deliberately does **not** reload ExyliaLib — recolouring every plugin on the server is what
`/exylialib reload` is for.

<Callout type="warning" title="A reload republishes the catalogue">
Effects are recompiled before the new catalogue is published, so nothing plays a half-compiled
sequence. But an effect whose key you renamed is a new effect: anyone wearing the old one loses it,
and any weapon bound to it now carries an id the file no longer declares.
</Callout>
