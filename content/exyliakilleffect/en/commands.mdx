## Player commands

`/killeffect`, with the aliases `killeffects`, `deatheffect` and `deatheffects`. Everything under it
needs `exyliakilleffect.command.killeffect`.

| Command | What it does |
|---|---|
| `/killeffect` | Opens the menu, on the tab it was last left on. |
| `/killeffect preview <effect>` | Plays an effect against an empty sky. Owning it is not required. |
| `/killeffect visibility [mode]` | Sets who sees kill effects for them. With no mode it steps to the next one. |
| `/killeffect favourites` | Opens the menu straight onto the shortlist. Aliases: `favorites`, `favs`. |
| `/killeffect favourite <effect>` | Stars an effect, or unstars it. Aliases: `favorite`, `fav`. |
| `/killeffect favourites clear` | Empties the shortlist. |
| `/killeffect clear` | Takes the effect off. |

## Admin commands

`/killeffectsadmin`, alias `/killeffectadmin`. Everything under it needs `exyliakilleffect.admin`.

| Command | What it does |
|---|---|
| `give <player> <effect> [1-64]` | Gives effect tokens. |
| `remover <player> [1-64]` | Gives effect removers. |
| `bind <effect> [player]` | Binds an effect to the weapon in hand, replacing whatever it carried. |
| `unbind [player]` | Strips the effect from the weapon in hand, giving nothing back. |
| `set <player> <effect>` | Sets what a player wears. |
| `clear <player>` | Takes a player's effect off. |
| `favourites clear <player>` | Empties a player's shortlist. |
| `validate [player]` | Takes off an effect the target may no longer use. With no player, everyone online. |
| `open <player>` | Opens the menu for someone. |
| `preview <effect> [player]` | Previews an effect, for yourself or for someone else. |
| `list [category]` | Prints every effect, or just one category's. |
| `refresh [player]` | Redraws what a player is holding. With no player, everyone online. |
| `reload` | Re-reads this plugin's files. |

<Callout type="note" title="bind, set and give ignore permissions">
They are admin verbs: a crate, a rank reward or a support ticket has already decided the player may
have the effect. `require-permission` governs what a **player** can do, never what an admin or the
API does.
</Callout>

## What each one actually does

### `bind`

Acts on the target's main hand. An empty hand answers `empty-hand`. A weapon that already carries an
effect has it replaced — the old one is dropped, not returned as a token. The weapon that does not fit
the effect's `weapons` list is refused.

### `unbind`

Strips the value and hands nothing back, which is the difference from a remover item. For giving the
token back, have the player use a remover.

### `validate`

Re-checks the target's choice against their permissions and takes it off if it no longer holds. The
same check runs on join, on the next kill and on every menu open — `validate` is how you make it
immediate after changing a rank.

### `refresh`

Re-sends the player's inventory so the lines under a bound weapon are redrawn. It touches no file and
plays no effect: it is the answer to a weapon whose line went stale.

### `reload`

Runs one step, `configs`, which re-reads `config.yml`, `effects.yml` and `menus/effects.yml`,
recompiles every sequence and reapplies the message prefix. Edits made to the menu file survive.

It deliberately does **not** reload ExyliaLib — recolouring every plugin on the server is what
`/exylialib reload` is for.

<Callout type="warning" title="A reload republishes the catalogue">
Effects are recompiled before the new catalogue is published, so nothing plays a half-compiled
sequence. But an effect whose key you renamed is a new effect: anyone wearing the old one loses it,
and any weapon bound to it now carries an id the file no longer declares.
</Callout>
