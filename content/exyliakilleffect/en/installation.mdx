## Installing

<Steps>
  <Step title="Drop in the jars">
    `ExyliaKillEffect.jar`, plus `ExyliaLib` and `packetevents`, into `plugins/`.
  </Step>
  <Step title="Start the server">
    It writes `config.yml`, `effects.yml` and `menus/main.yml`, and creates its table.
  </Step>
  <Step title="Grant the permissions">
    Nothing is usable until players can open the menu and own at least one effect. See
    [Commands and permissions](/docs/exyliakilleffect/commands).
  </Step>
</Steps>

## Files

| File | Contents |
|---|---|
| `config.yml` | Which kills count, the default visibility, and the names of the visibility modes. |
| `effects.yml` | The 14 categories and 144 effects. |
| `menus/main.yml` | The menu layout, editable like any ExyliaLib menu. |
| `database.yml` | Where selections are stored. H2 by default. |

Selections live in the `killeffect_players` table: the chosen effect and the visibility mode, per
player.

## config.yml

```yaml
placeholders:
  none: "None"

effects:
  all-mobs: false
  allowed-mobs:
    - PLAYER
    - MANNEQUIN
    - ZOMBIE

particles:
  default-visibility: "ALL"
  name-all: "All"
  name-none: "None"
  name-self-only: "Self Only"
  name-others-only: "Others Only"
```

| Key | Default | What it does |
|---|---|---|
| `placeholders.none` | `None` | What the placeholders show when a player has no effect chosen. |
| `effects.all-mobs` | `false` | `true` plays the effect on any kill. `false` limits it to the list below. |
| `effects.allowed-mobs` | `PLAYER`, `MANNEQUIN`, `ZOMBIE` | Entity types whose death plays an effect. |
| `particles.default-visibility` | `ALL` | What a player starts with: `ALL`, `NONE`, `SELF_ONLY`, `OTHERS_ONLY`. |
| `particles.name-*` | see above | How each mode is named in menus and placeholders. |

<Callout type="tip" title="all-mobs on a farming server">
`all-mobs: true` means every zombie in a grinder fires a full sequence. The default list exists
because a kill effect is usually meant for PvP: keep it limited unless you want particles on every
mob death.
</Callout>

## Updating

Replace the jar and restart. `/killeffect reload` re-reads the plugin's own files without touching the
rest of the server.
