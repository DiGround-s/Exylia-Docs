## The file

`effects.yml` has two sections: the categories, and the effects that belong to them.

```yaml title="effects.yml"
categories:
  impact:
    material: NETHERITE_SWORD
    name: 'Impact'
    priority: 1

hit_effects:
  CRIT_SPARK:
    category: impact
    name: "<gradient:#FFE9A8:#D1A53F><bold>CRIT SPARK</bold></gradient>"
    material: GOLDEN_SWORD
    description: "Eight splinters of gold, {highlight}gone in a third<nl>of a second{neutral}."
    priority: 1
    effects:
      - '[SOUND] ENTITY_PLAYER_ATTACK_CRIT;0.7;1.4'
      - '[SPHERE] GOLD_BLOCK;as:block;radius:0.25;points:8;size:0.14;size_to:0.02;pull:-4;ease:out;life:0.32;spin:1,1,1;vary:0.6;light:15;glow:{highlight}'
      - '[PARTICLE] CRIT;count:12;offset:0.3,0.3,0.3;speed:0.15'
```

| Key | What it does |
|---|---|
| `category` | Which tab it appears under. Must be a key declared under `categories`. |
| `name` | What menus and placeholders call it. Palette tokens, MiniMessage and gradients all work. |
| `material` | The item the row is drawn with. Defaults to `BARRIER`. |
| `description` | A list is one line per entry; a single string breaks on `<nl>`. |
| `priority` | Where it sits in its tab; lower comes first. Defaults to `999`. |
| `effects` | The steps drawn on whoever was hit. |
| `weapons` | Optional. What the effect may be bound to. Omit it and it fits anything. |

A category takes `material`, `name` and `priority`.

<Callout type="note" title="Broken entries are reported, not guessed">
A missing `categories` section, an effect naming a category that is not declared, an entry with no
`effects`, and a `weapons` token that is neither an item nor a family are each written to the console
with the key that caused them. The rest of the file still loads.
</Callout>

## `weapons`

Only read while `behaviour.mode` reads weapons. It accepts item names and families:

```yaml
weapons: [ NETHERITE_SWORD, AXE ]
```

| Family | Matches |
|---|---|
| `ANY` | Anything at all. |
| `SWORD` | Every `_SWORD`. |
| `AXE` | Every `_AXE` — a pickaxe is not one. |
| `TRIDENT`, `MACE`, `BOW`, `CROSSBOW` | Just that item. |
| `MELEE` | Swords, axes, tridents and maces. |
| `RANGED` | Bows, crossbows and tridents. |

Families are matched on the item's name, so a sword added in a future Minecraft version is a sword the
day it exists. `ANY_SWORD` reads the same as `SWORD`. None of the shipped effects declares `weapons`,
so out of the box every one of them fits every weapon.

<Callout type="note" title="The effect id is the permission">
`CRIT_SPARK` is `exyliahiteffect.effect.crit_spark`. Renaming the key renames the node, and everybody
who had the old one loses the effect. Case is not part of it: ids are lowercased on the way in.
</Callout>

## Where an effect is drawn

The anchor is **a block above the victim**, so the effect lands on the body rather than at its feet.
`(0,0,0)` in a step is that point.

## Writing your own

<Steps>
  <Step title="Add the entry">
    A new key under `hit_effects`, with a `category` that exists.
  </Step>
  <Step title="Keep it inside the budget">
    Under six tenths of a second, ten displays at most, quiet, about a block wide. The full syntax is
    in [Sequences](/docs/exyliahiteffect/sequences).
  </Step>
  <Step title="Reload">
    `/hiteffectsadmin reload`.
  </Step>
  <Step title="Look at it">
    `/hiteffect preview <id>` plays it against an empty sky, then puts you back.
  </Step>
  <Step title="Grant it">
    `exyliahiteffect.effect.<id in lowercase>`, or the whole category.
  </Step>
</Steps>

<Callout type="warning" title="A hit effect is not a kill effect">
The same syntax draws both, and it is tempting to paste a ten-second production in here. On a busy
arena that is one of those per blow, per player, on every client in range.
</Callout>
