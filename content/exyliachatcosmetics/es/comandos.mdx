description: "Todos los comandos que registra el plugin: el de jugador, los cuatro atajos, el de administración y los del módulo de chat."
---

Los comandos se registran con Lamp, así que cada argumento se autocompleta y uno mal escrito se
rechaza antes de que se ejecute nada. Hay dos convenciones que valen en todas partes:

- `<key>` es siempre un cosmético escrito como `type:id` — `tag:mvp`, `chat_color:aurora`,
  `customtag:42`. Se autocompleta con lo que quien pregunta puede ver de verdad.
- `<player>` en un comando de administración acepta a alguien desconectado, siempre que haya entrado
  antes a este servidor. Un nombre con el que nunca ha entrado nadie se rechaza en vez de convertirse
  en un uuid offline nuevo que nadie va a leer jamás.

## El comando de jugador

`/chatcosmetics`, `/cosmetics` y `/cc` son el mismo comando. Todo él va detrás de
`exyliachatcosmetics.command.cosmetics`, declarado como `default: true`, así que en una instalación
nueva lo tiene todo el mundo.

Todo lo que hay aquí es también un clic en un menú. Los comandos existen para los jugadores que
prefieren escribir, y para los servidores que los ponen en un cartel o en un botón.

### Pantallas

| Comando | Abre |
|---|---|
| `/cc` | el menú principal |
| `/cc tags` | el navegador de etiquetas |
| `/cc customtags` | el navegador de etiquetas que los jugadores se escribieron |
| `/cc nick` | colores de nick |
| `/cc rank` | colores de rango |
| `/cc colors` | colores de chat |
| `/cc shadows` | colores de sombra |
| `/cc customcolors` | el navegador de colores de chat personalizados |
| `/cc fonts` | fuentes |
| `/cc modifiers` | modificadores |
| `/cc favorites` | todo lo que marcó con estrella, de cualquier tipo |
| `/cc loadouts` | el menú de loadouts |

### Ponerse cosas

| Comando | Hace |
|---|---|
| `/cc equip <key>` | se lo pone. Un modificador que ya lleva puesto se lo quita: los modificadores se acumulan, así que equiparlo dos veces lo alterna. Los demás tipos llevan una sola cosa a la vez, así que la nueva reemplaza a la anterior. |
| `/cc unequip <type>` | se quita todo lo de ese tipo |
| `/cc favorite <key>` | lo marca con estrella, o se la quita si ya la tenía |
| `/cc preview [message]` | dibuja en el chat su propia línea. Sin mensaje usa `menu.sample-message`. |
| `/cc tokens` | lo que le queda para crear y para editar, por tipo |

### Loadouts

| Comando | Hace |
|---|---|
| `/cc loadout save <name>` | guarda lo que lleva puesto ahora; un loadout con ese nombre se sobrescribe |
| `/cc loadout load <name>` | se lo vuelve a poner; lo que ya no posee se salta |
| `/cc loadout delete <name>` | |
| `/cc loadout list` | todos sus loadouts con lo que llevan |

### Crear cosas

| Comando | Hace |
|---|---|
| `/cc customtag create <text> [color]` | escribe una etiqueta propia; gasta un token `create` y obedece las reglas de texto de `custom-tags` |
| `/cc customtag delete` | borra todas las etiquetas que ese jugador hizo |
| `/cc customcolor create <spec>` | mezcla un color de chat: `#hex`, o `#a:#b` y `#a:#b:#c` para un degradado |
| `/cc customnick create <spec>` | lo mismo, para el nombre |
| `/cc customrank create <spec>` | lo mismo, para el prefijo y el sufijo del rango |
| `/cc customcolor delete <id>` · `customnick delete <id>` · `customrank delete <id>` | borra uno por su id; el token no vuelve |

<Callout type="note" title="Borrar no devuelve nada">
El token `create` se gasta al escribir el cosmético, no queda retenido por él. Borrarlo libera el
hueco en el menú y nada más, y eso es lo que impide que un jugador cree y descree para siempre con
una sola compra. Ver [Tokens](/docs/exyliachatcosmetics/tokens).
</Callout>

## Los cuatro atajos

Cuatro comandos de primer nivel abren una pantalla directamente, una palabra cada uno, porque un
jugador que sabe lo que quiere no debería tener que acordarse de qué plugin lo lleva. Llevan el mismo
permiso `exyliachatcosmetics.command.cosmetics` que `/cc`.

| Comando | Abre |
|---|---|
| `/tags` | el navegador de etiquetas — la misma pantalla que `/cc tags` |
| `/nickcolors` | colores de nick |
| `/rankcolors` | colores de rango |
| `/chatcolors` | la pantalla del mensaje, no un navegador: el color de chat es una de las varias cosas que lleva, junto a la sombra, la fuente y los modificadores |

## El comando de administración

`/chatcosmeticsadmin`, `/exyliachat` y `/cca` son el mismo comando, detrás de
`exyliachatcosmetics.admin` (`default: op`).

### Concesiones

| Comando | Hace |
|---|---|
| `/cca give <player> <key> [duration] [--source <name>] [--ref <id>] [--note <text>]` | añade una concesión. Sin duración es permanente. La fuente por defecto es `ADMIN`; `--source` acepta `PURCHASE`, `REWARD`, `EVENT`, `ACHIEVEMENT` y `EXTERNAL`, y lo que no reconoce lo guarda como `EXTERNAL` en vez de rechazarlo. |
| `/cca remove <player> <key> [source]` | revoca todas las concesiones activas de ese cosmético, o solo las de esa fuente |
| `/cca revoke <id>` | revoca una concesión por el id de fila que imprime `list` |
| `/cca list <player>` | todas las concesiones activas, con su id, su fuente y el tiempo que les queda |
| `/cca check <player> <key>` | si lo posee, y hasta cuándo |

Las duraciones son las de ExyliaLib: `30m`, `2h`, `14d`, `1w`, con decimales.

### Lo que lleva puesto un jugador

| Comando | Hace |
|---|---|
| `/cca equip <player> <key>` | se lo pone a alguien conectado. Tiene que poseerlo ya: esto no es una concesión. |
| `/cca unequip <player> <type>` | le quita todo lo de ese tipo |
| `/cca clear <player>` | se lo quita todo |

### Lo que un jugador hizo

| Comando | Hace |
|---|---|
| `/cca customtag set <player> <text> [color]` | le escribe una etiqueta propia. No gasta token, pero sigue obedeciendo las reglas de texto. |
| `/cca customtag clear <player>` | borra todas sus etiquetas propias |
| `/cca customcolor clear <player>` · `customnick clear` · `customrank clear` | lo mismo, por cada tipo de color personalizado |
| `/cca loadouts clear <player>` | borra todos sus loadouts |

### Tokens

| Comando | Hace |
|---|---|
| `/cca tokens give <player> <type> <create\|edit> <amount>` | suma a un saldo. El destinatario puede estar desconectado: un saldo es una fila propia y lo espera, igual que una concesión. |
| `/cca tokens take <player> <type> <create\|edit> <amount>` | resta de él, nunca por debajo de cero |
| `/cca tokens set <player> <type> <create\|edit> <amount>` | lo fija de golpe |
| `/cca tokens check <player>` | todos los saldos que tiene, por tipo |

`<type>` aquí es uno de los tipos que un jugador puede escribirse: `customtag`, `customcolor`,
`customnick`, `customrank`. Nombrar un tipo del catálogo se rechaza: ahí no se crea nada, así que no
hay nada que un token pueda pagar. La clase es `create` o `edit`.

### Mirar a alguien

| Comando | Hace |
|---|---|
| `/cca preview <player> [message]` | te manda la línea que dibujaría el chat de ese jugador |
| `/cca render <player>` | te manda las piezas de una en una: la etiqueta, el nombre en su color, y un mensaje de muestra con su fuente, sus modificadores y su color |
| `/cca reload` | cinco pasos en orden, cada uno reportado por su nombre |

`/cca reload` ejecuta `configs` (`config.yml` y `messages.yml`), `catalogs` (`cosmetics/*.yml`),
`menus` (`menus/*.yml`), `chat` (instala o desinstala el hook, y arranca o para el módulo según
`chat.module.enabled`) y `hooks`, que reintenta el puente con LuckPerms. Ese último paso es la razón
por la que un reload es la forma de recoger un LuckPerms que terminó de cargar después que este
plugin: los colores de rango pasan de vacíos a funcionar sin reiniciar.

El paso `menus` se ejecuta además con el reload de la propia ExyliaLib. Un menú guarda la paleta con
la que se compiló, así que un servidor repintado se quedaría con los colores viejos hasta que alguien
volviera a leer los archivos.

<Callout type="note" title="Reload es solo de este plugin">
`/cca reload` no recarga ExyliaLib. Repintar todos los plugins del servidor desde `colors.yml` es
para lo que está `/exylialib reload`.
</Callout>

### El módulo de chat

Estos solo responden mientras el módulo de chat está en marcha. Con él apagado lo dicen y no cambian
nada.

| Comando | Hace |
|---|---|
| `/cca chat line [message]` | imprime tu propia línea de chat partida en los tramos que comparten un hover y un clic, a la consola y a ti. Un hover que se pasa un componente de largo se ve aquí en vez de adivinarse desde una captura. |
| `/cca chat reload` | vuelve a leer los archivos propios del módulo, en `chat/`, sin tocar los cosméticos |
| `/cca chat similar <a> <b>` | cuánto se parecen dos líneas, como el número que el filtro de similitud compara con su umbral |
| `/cca chat regex <word>` | el patrón al que compila una palabra de regla, listo para pegar en una regla avanzada |
| `/cca chat points <player> [set]` | lee los puntos de infracción de un jugador, o escribe un total nuevo |
| `/cca chat announce <id>` | manda ese anuncio ahora; `next` manda el que toque |

## Los comandos propios del módulo de chat

Estos son del módulo, no de los cosméticos, y cada uno se registra solo mientras su interruptor en
`chat/config.yml → commands` está encendido. Los nueve vienen encendidos. Apagar uno no lo esconde
detrás de un permiso: no se registra en absoluto, y así es como te quedas con el `/msg` que ya lleva
tu plugin de siempre.

```yaml title="plugins/ExyliaChatCosmetics/chat/config.yml"
commands:
  msg: true
  reply: true
  ignore: true
  ignoreall: true
  spymsg: true
  mutechat: true
  clearchat: true
  broadcast: true
  channel: true
```

| Comando | Permiso | Hace |
|---|---|---|
| `/msg` `/tell` `/w` `/whisper <player> <message>` | `exyliachatcosmetics.chat.command.msg` | susurra |
| `/reply` `/r <message>` | `…chat.command.reply` | responde al último susurro |
| `/ignore <player>` | `…chat.command.ignore` | alterna ignorarlo; al staff no se le puede ignorar |
| `/ignoreall` `/msgtoggle` `/togglemsg` | `…chat.command.ignoreall` | cierra o abre el buzón |
| `/spymsg` `/socialspy` | `…chat.command.spymsg` | lee los susurros de todo el mundo |
| `/mutechat` | `…chat.command.mutechat` | silencia y devuelve el chat |
| `/clearchat` | `…chat.command.clearchat` | empuja el chat fuera de la pantalla de todos |
| `/broadcast` `/bc <message>` | `…chat.command.broadcast` | una línea del servidor |
| `/channel` `/ch <id>` | `…chat.command.channel` | mueve los mensajes normales del jugador a ese canal |

Hay uno más que se registra siempre, sin interruptor y sin permiso: `/chatcosmeticsrender <id>` es lo
que ejecuta un clic sobre un `[item]` mostrado. No está pensado para escribirse — el id es aleatorio,
así que no hay nada que adivinar.
