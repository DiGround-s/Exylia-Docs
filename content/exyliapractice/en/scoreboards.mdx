`scoreboards.yml` holds **nineteen** sidebars. Each has the same shape:

```yaml
lobby:
  enabled: true
  title:
    - "{primary}&lPRACTICE"
  lines:
    - ""
    - " {info}🌎 {letters}Online: {success}%server_online%"
    - " {highlight}exylia.net"
  update:
    interval: 10
    smart: true
    cache: true
```

`title` is a list: several entries animate through them. `update.interval` is in **ticks**.

## The nineteen

| Key | Shown to |
|---|---|
| `lobby` | A player in the lobby with no party |
| `party` | A player in the lobby who is in a party |
| `queue` | A queued player |
| `game` | A 1v1 with no points and no hit target |
| `game-points` | A 1v1 with `points-to-win` |
| `game-hits` | A 1v1 with `hits-to-win` |
| `duel` | A multi-round duel |
| `duel-points` | A multi-round duel with points |
| `duel-hits` | A multi-round duel with a hit target |
| `party-ffa` | A party free-for-all |
| `party-team` | A party split or party duel |
| `spec-game` | Spectating a plain 1v1 |
| `spec-game-points` | Spectating a 1v1 with points |
| `spec-game-hits` | Spectating a 1v1 with hits |
| `spec-duel` | Spectating a duel |
| `spec-duel-points` | Spectating a duel with points |
| `spec-duel-hits` | Spectating a duel with hits |
| `spec-party-ffa` | Spectating a party FFA |
| `spec-party-team` | Spectating a party team match |

The right one is picked automatically from the match mode, whether the kit has `points-to-win`, and
whether it has `hits-to-win` — points win the tie when both are set.

A player who has turned the scoreboard off in `/settings` sees none of them.

## Tokens by sidebar

Alongside these, every [placeholder](/docs/exyliapractice/placeholders) and every other plugin's
placeholders resolve inside a sidebar line.

### Lobby and party

| Token | Answers |
|---|---|
| `%server_online%` | Players online on the server |
| `%queue%` | Players queued server-wide |
| `%fighting%` | Players in a match server-wide |
| `%wins%` | The reader's global wins |
| `%kdr%` | Their global kill/death ratio, one decimal |
| `%win_rate%` | Their global win rate as a percentage |
| `%mmr%` | Their global rating |
| `%rank%` | The rank's name on its own: `Copper` |
| `%rank_division%` | The division on its own: `II`. Empty for a rank that has none |
| `%rank_name%` | The rank and its division together: `Copper II` |
| `%rank_lp%` | LP inside the current division |
| `%rank_lp_max%` | The division's width in LP |
| `%rank_icon%` | The rank's icon |
| `%members%` | How many players are in the party. `party` only |
| `%max%` | The party's maximum size. `party` only |
| `%leader%` | The party leader's name. `party` only |

### Queue

| Token | Answers |
|---|---|
| `%kit%` | The first kit queued for, with `+N` when there are more |
| `%time%` | How long they have been waiting |
| `%queue%` | Players queued server-wide |
| `%fighting%` | Players in a match server-wide |
| `%wins%` | The reader's global wins |
| `%kdr%` | Their global kill/death ratio, one decimal |
| `%win_rate%` | Their global win rate as a percentage |
| `%mmr%` | Their rating on the first kit queued for |
| `%rank%` | That kit's rank name on its own |
| `%rank_division%` | That rank's division on its own |
| `%rank_name%` | That rank and its division together |
| `%rank_lp%` | LP inside that division |
| `%rank_lp_max%` | That division's width in LP |
| `%rank_icon%` | That rank's icon |

The rank tokens here are the rating on **that first kit**, not the global one. `%server_online%` is
not filled in on this sidebar; the queue board is built without it.

### In a match

| Token | Answers |
|---|---|
| `%kit%` | The kit's name |
| `%arena%` | The arena's name |
| `%time%` | Match duration |
| `%my_points%` | The reader's points |
| `%their_points%` | The opponent's points |
| `%points_to_win%` | The kit's `points-to-win` |
| `%hits%` | Hits **received** by the reader |
| `%opp_hits%` | Hits **received** by the opponent |
| `%hits_to_win%` | The kit's `hits-to-win` |
| `%round%` | The current duel round |
| `%total_rounds%` | How many rounds the duel is played over |
| `%my_wins%` | Rounds the reader has won |
| `%their_wins%` | Rounds the opponent has won |
| `%my_ping%` | The reader's latency |
| `%opp_ping%` | The opponent's latency |
| `%alive%` | Players still alive |
| `%total%` | Players the match started with |
| `%team_a_alive%` | Team A survivors |
| `%team_b_alive%` | Team B survivors |
| `%mmr%` | The reader's rating on the kit being played |
| `%rank%` | Their rank name on that kit, on its own |
| `%rank_division%` | That rank's division on its own |
| `%rank_name%` | That rank and its division together |
| `%rank_lp%` | LP inside that division |
| `%rank_lp_max%` | That division's width in LP |
| `%rank_icon%` | That rank's icon |
| `%opponent%` | The opponent's name, 1v1 only |
| `%opp_mmr%` | The opponent's rating on the kit, 1v1 only |
| `%opp_rank%` | The opponent's rank name on its own |
| `%opp_rank_division%` | Their division on its own |
| `%opp_rank_name%` | Their rank and division together |
| `%opp_rank_lp%` | Their LP inside that division |
| `%opp_rank_lp_max%` | That division's width in LP |
| `%opp_rank_icon%` | Their rank's icon |

The reader's own rank tokens in a match are their rating **on the kit being played**. The opponent
tokens are filled in for a 1v1 and answer `?` or `0` in every other mode.

Three more are filled in only when the match is against bots:

| Token | Answers |
|---|---|
| `%bot_mode%` | The combat mode the bots are fighting in |
| `%bot_difficulty%` | The difficulty they were spawned at |
| `%bots_alive%` | How many bots are still alive |

### Spectating

A spectator sidebar names the two sides rather than the reader, so it has no `%my_*%` or `%their_*%`
tokens at all:

| Token | Answers |
|---|---|
| `%kit%` | The kit's name |
| `%arena%` | The arena's name |
| `%time%` | Match duration |
| `%round%` | The current duel round |
| `%total_rounds%` | How many rounds the duel is played over |
| `%points_to_win%` | The kit's `points-to-win` |
| `%hits_to_win%` | The kit's `hits-to-win` |
| `%alive%` | Players still alive |
| `%total%` | Players the match started with |
| `%team_a_alive%` | Team A survivors |
| `%team_b_alive%` | Team B survivors |
| `%player1_name%` | The first player's name |
| `%player1_ping%` | Their latency |
| `%player1_points%` | Their points |
| `%player1_hits%` | Hits they have **received** |
| `%player1_wins%` | Rounds they have won |
| `%player1_rank%` | Their rank name on its own |
| `%player1_rank_division%` | Their division on its own |
| `%player1_rank_name%` | Their rank and division together |
| `%player1_rank_lp%` | Their LP inside that division |
| `%player1_rank_lp_max%` | That division's width in LP |
| `%player1_rank_icon%` | Their rank's icon |
| `%player2_name%` | The second player's name |
| `%player2_ping%` | Their latency |
| `%player2_points%` | Their points |
| `%player2_hits%` | Hits they have **received** |
| `%player2_wins%` | Rounds they have won |
| `%player2_rank%` | Their rank name on its own |
| `%player2_rank_division%` | Their division on its own |
| `%player2_rank_name%` | Their rank and division together |
| `%player2_rank_lp%` | Their LP inside that division |
| `%player2_rank_lp_max%` | That division's width in LP |
| `%player2_rank_icon%` | That rank's icon |

The two player sets are filled in for a spectated 1v1 only. There is no `%player1_mmr%` or
`%player2_mmr%`: the rating itself is not part of a spectator context, only the rank it maps to.

## The match action bar

Separate from the sidebar, and configured under `game.match-actionbar` in `config.yml`:

```
%opponent_health% | %hits_dealt%↑%my_combo% %hits_received%↓%combo_received%
| %damage_dealt%⚔ / %damage_received%⚔ | %accuracy% / %opponent_accuracy%🎯
| %my_ping%ms / %opponent_ping%ms
```

## Titles and sounds

The match's other visuals live in `config.yml` rather than here:

| Key | When |
|---|---|
| `game.countdown-title` | Each second of the pre-match countdown, with `%time%` |
| `game.fight-title` | The moment the match starts |
| `game.you-won-title`, `game.you-lost-title`, `game.draw-title` | The result |
| `duel.round-won-title`, `duel.round-lost-title`, `duel.round-draw-title` | Between rounds, with `%my_wins%` and `%their_wins%` |
| `queue.match-found-title`, `queue.match-found-actionbar` | While the arena is being prepared |
| `queue.in-queue-actionbar` | While queued, with `%kits%`, `%time%` and `%elo%` |
| `queue.teaser-bossbar` | The rotating queue advertisement |
| `pvp-regions.combat-tag-bossbar` | While combat-tagged in a PvP zone, with `%time%` |
| `season.progress-bossbar` | During a season rotation, with `%phase%` and `%percent%` |

Each of those blocks is a full effect definition — a title, an action bar, a boss bar, a sound, a
particle and a firework — so any of them can carry more than the one thing its name suggests.
